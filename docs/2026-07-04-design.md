## 1. 定位

**zcode-tui 是官方 ZCode 的第三方终端加法，不是替代品。**

**第一使用场景：SSH 无桌面环境。** 官方只发桌面版，而终端用户（尤其是 SSH
到无桌面服务器的用户）需要一个能直接干活的界面。因此 TUI 自身必须保持纯终端
依赖（无剪贴板/通知/浏览器假设），内核引导链路必须在无 GUI 库的机器上走通
（见 7.1 节）。

背景事实（2026-07-04 验证）：官方 ZCode 桌面包（Linux Beta，最新 3.2.5）内嵌
headless CLI 内核 `resources/glm/zcode.cjs`，其 `tui` 子命令因缺少 `@zcode/tui`
包而不可用——该包未随 deb 发货、未发布到公共 npm、changelog 未提及。官方 CLI
help 表明 TUI 在其计划内（"With no command, zcode opens the full-screen TUI"）。

由此确立三条边界原则：

1. **内核的事只调用、不重造**：模型推理、会话存储、权限体系、工具执行、
   checkpoint 全部属于 `zcode.cjs`；本项目是它的终端前端。
2. **不模仿桌面版**：图形会话管理、托管其他 agent、账号订阅界面不做。
3. **官方 TUI 发布即退位**：wrapper 在每次运行时探测 `@zcode/tui` 能否解析，
   一旦官方发货，`zcode tui` 自动交还官方实现，本项目无声让位；届时仍有
   独立价值的加法功能（git 工作流、上下文供给、secret 防呆）可拆出续存。

## 2. 系统架构

```
终端
 └─ ~/.local/bin/zcode          bash wrapper（install.sh 生成，带管理标记）
     ├─ 运行时探测 app 目录：$ZCODE_APP → /opt/ZCode → ~/.local/opt/zcode/*/opt/ZCode
     ├─ tui / 裸调用：探测 @zcode/tui 可解析？
     │    ├─ 是 → 交给官方 TUI
     │    └─ 否 → exec ~/.local/bin/zcode-tui（本项目，ZCODE_TUI_ZCODE_BIN 指回 wrapper）
     └─ 其他子命令 → ELECTRON_RUN_AS_NODE=1 /opt/ZCode/zcode zcode.cjs "$@"
                     （内核需要 node:sqlite ≥ Node 22.5，优先 Electron 内嵌 Node；
                      Electron 起不动——无桌面机器缺 GUI 库——则探测后回退系统
                      node ≥ 22.5，ZCODE_FORCE_SYSTEM_NODE=1 强制，均不可用则报错退出）

zcode-tui（Rust，单一静态二进制 5.3MB）
 ├─ src/lib.rs   (~2000 行) 纯逻辑层：无 ratatui 依赖，全部可单测
 │    输入分类 / 命令目录 / 补全 / markdown+高亮 / diff / MCP 配置 /
 │    认证检测 / 更新 feed 解析 / 流式子进程 / CJK 宽度工具
 ├─ src/main.rs  (~1900 行) 渲染与事件层：Theme、布局、按键、任务泵、启动探测线程
 └─ tests/core.rs (37 个集成测试)
```

### 2.1 流式任务模型（核心机制）

每个会跑子进程的动作（prompt / shell / diff）走同一条路径：

- `spawn_streaming_command`：子进程放入**独立进程组**（`process_group(0)`），
  stdout/stderr 各起一个 reader 线程按行发 `JobEvent::Line`，行尾发
  `JobEvent::Eof`；waiter 线程轮询 `try_wait` 发 `JobEvent::Finished`。
- UI 主循环 80ms 轮询：泵事件 → 追加 transcript → 重绘。
- **收尾条件**：`Finished` 已到 **且** 收齐全部流的 `Eof`（无损，不丢尾部输出）；
  1.5s 超时兜底孙进程占管道的病态情况。
- **取消**：Esc/Ctrl+C → `killpg` 杀整个进程组（防 `sh -lc` 的孙进程残留）。
- 忙时新输入进 FIFO 队列，空闲时自动提交。
- **prompt 通道（0.2.0 起）**：附 `--json`，stdout 行运行中只缓冲不上屏；
  收尾解析整块总结对象为权威结果（response → markdown、sessionId、usage、
  contextUsed → 状态栏水位，≥80% 提示 /new），解析失败按纯文本路径降级。
  运行中的实时反馈来自 db 轮询（5.1）：主循环每 5 拍（~400ms）只读查询
  tool_usage/part，工具 chip 与 reasoning dim 行渲染在 composer 上方的
  工作区，turn 结束整体清场,不进 transcript。会话锁定:resume 用显式 id、
  continue 按目录取最新、全新会话记 spawn 前最新会话为 prior 并在轮询中
  排除之（新会话行 ~1.6s 落库后自动锁定）。

### 2.2 会话连续性状态机

headless 内核按 cwd 维护会话，TUI 负责把独立的 `--prompt` 调用串成对话：

- 首条 prompt 成功 → `session_active=true`，后续自动附 `--continue`
- `/new` → 清位 + 清屏（上下文重置）
- `/resume`（裸）→ `--continue`；`/resume sess_x` → 固定 `--resume sess_x`
- `/mode`、`Shift+Tab` → 改 `config.mode`，作用于后续每条命令
- 欢迎框实时显示 `session: fresh / continuing latest / resume sess_x`

### 2.3 启动探测线程

启动时后台线程（不阻塞首帧）依次探测，结果经 mpsc 回主循环：

1. 内核版本：`zcode version`
2. 已装桌面包版本：`dpkg-query -W zcode`（取 `-` 前段）
3. 官方更新：读 `app-update.yml` 得 electron-updater feed URL →
   `curl latest-linux.yml`（**与桌面端同一发布渠道**，提示内容天然与官网一致）
   → 版本比较 → 新版则插入 ASCII logo + Tip 单元（changelog 链接 + deb 直链）
   `ZCODE_TUI_NO_UPDATE_CHECK=1` 跳过网络。

## 3. 视觉设计语言

**Codex 范式外壳 + 智谱配色**（参照 Codex CLI 实拍截图逐项复刻）：

- **零边框**：无侧栏、无常驻头部框；transcript 无边框流式排版，条目间空行
- **底色横条代替边框**：用户消息和 composer 用抬升底色 `RGB(48,52,63)` +
  `›` 前缀；会话信息是 transcript 第一个单元（圆角欢迎框，unicode-width 对齐）
- **单元标记**：助手 `•`、系统 `•`(dim)、错误 `✗`、工具 `⚙/↳`、引用 `>`（绿）
- **单一强调色锁定**（taste 纪律）：GLM 蓝 `RGB(96,136,255)` 是唯一强调色——
  `›`、行内代码、链接、spinner、logo 大字；绿/红仅语义状态（diff、错误）；
  中点符号每行限一个；无装饰性噪音文案
- **主题 token**：`accent / accent_dim / text / dim / good / bad / frame /
  code_bg / band_bg / brand / brand_dim`，`--no-color` 或 `NO_COLOR` 全部
  退化为无色。`brand`（清华紫亮化 RGB(178,108,196)）与 `brand_dim`
  （暗紫 RGB(122,42,134)）为 logo 专属——仅用于未登录屏字标（块体亮紫、
  描边暗紫成阴影层）与鸟巢/长城/天坛轮廓，交互元素仍锁 GLM 蓝。
  全部 token 可经 `~/.config/zcode-tui/config`（行式 key=value，自研解析、
  无 TOML 依赖，坏值静默忽略）覆盖,`mouse = off` 关闭滚轮捕获;
  NO_COLOR 优先级仍最高。长输出折叠(Tool/System/Diff/Error > 24 行折为
  头 8 行 + Ctrl+O)与鼠标滚轮回看同属 0.3.0 舒适度批
- 弹层（补全/命令面板/帮助）：圆角细框，是唯一保留边框的浮动元素

| 内容 | 处理 |
|---|---|
| 助手回复 | pulldown-cmark（启用表格）→ StyledLine → 主题映射 |
| 代码块 | syntect 语法高亮（`regex-fancy` 纯 Rust，base16-ocean），未知语言纯底色 |
| ` ```diff ` 围栏 | 按 diff_line_role 着色（+绿 −红 @@蓝 头加粗） |

## 4. 功能规格

### 输入路由

```
文本            → zcode --prompt（自动 --continue / --mode / --attach）
@路径           → canonicalize 校验在 cwd 内且为常规文件 → --attach
!cmd            → sh -lc 流式执行
/命令           → 本地(local) 或转发(zcode)，见 README 命令表
```

### 本地命令（TUI 自有）

会话：`/new` `/resume` `/sessions`（db 浮层选择器）`/mode`（+Shift+Tab）；
认证：`/login`（挂起 TUI 交互）
`/logout` `/auth`；工程：`/diff` `/ide` `/editor` `/status`；MCP 配置：
`/mcp add|add-json|get|list|enable|disable|remove`（project/user 两级 scope，
stdio/http/sse 三种 transport，`.mcp.json` 与 Claude Code 格式兼容，`--` 后
参数原样归 server）；透传：`/skills`。

### 补全

`/` 即时弹菜单（前缀 > 子串 > 子序列三级匹配）；`@` 文件路径补全（跳过
.git/target/node_modules 等，扫描上限 4000）；↑↓ 选择、Tab/Enter 接受、Esc 关闭。

### 认证模型

凭证归内核管（`~/.zcode/v2/credentials.json`），TUI 只做检测与代办：
env 链 `ZCODE_API_KEY → ZHIPUAI_API_KEY → ZAI_API_KEY`（打码显示）→ 凭证文件
候选；`/login` = 挂起终端跑 `zcode login`（Z.AI OAuth），可 env 覆盖。

## 5. 与官方内核的能力边界

headless `--prompt` 通道**做得到**：多轮会话（--continue/--resume）、模式、
附件、goal（--target，待接线）、skills/plugins/commands 列表。

**做不到**（需要内核的 `app-server` ZCode Protocol，按需评估、不主动追平）：

| 能力 | 说明 |
|---|---|
| 权限审批中继 | ~~--prompt 默认 yolo，edit/plan 的工具确认无人接住~~ → **已实现**（openspec 变更 `kernel-session-controls`）：app-server 路径接住 `interaction/requestPermission`（build 模式副作用工具）与 `interaction/requestUserInput`（plan 审批）两种服务器→客户端请求，确认浮层应答；--prompt 路径仍是 yolo（内核限制） |
| /model 切换 | ~~headless 无对应参数~~ → **已实现**：app-server `session/setModel`，/model 浮层；/think（setThoughtLevel）同批 |
| /compact /rewind /fork /expert | /compact **已实现**（app-server `session/compact`，原地压缩保会话）；rewind/fork/expert 仍未接（按需评估） |
| /mcp 运行态 | 只能管配置文件，看不到连接状态 |
| token 级流式 | ~~stdout 整块返回~~ → **已试验实现**：`ZCODE_TUI_APP_SERVER=1` 走 app-server `session/event` 逐 token 流式（openspec 变更 `app-server-streaming`，v0.4.0）；默认关闭、失败无缝降级回 --prompt。准流式 db 路径见 5.1 仍是默认。同路径后续加了 steer 中途转向与 setMode 即刻切换（`kernel-session-controls`） |

策略：协议接入只在某个加法确实需要时做客户端消费，不做协议层功能再造。
`app-server-streaming` 是第一个落地的协议客户端加法——一个可复用、可单测的
最小客户端地基（信封编解码 + 会话生命周期 + 降级判定在 lib.rs），后续
/model、权限中继等协议加法可共用。

### 5.1 db.sqlite 实测事实（2026-07-04 流式 spike）

内核在 turn 进行中**实时写入** `~/.zcode/cli/db/db.sqlite`（首个新 part 1.6s
即落库，工具行运行中逐个出现并完成；只读轮询 0.4s 间隔全程无锁冲突）。
这使"只读轮询 db"成为不碰 app-server 协议的准流式路径：

- `part`：完整事件流——`text` / `reasoning` / `tool`（callID、工具名、
  state）/ `step-start` / `step-finish`（cost、tokens）
- `tool_usage`：tool_name、read_only、destructive、approval_status、
  duration_ms、exit_code —— 工具调用展示的全部原料
- `input_history`：内核自己持久化输入历史（含 attachments）
- `session`：title、directory、summary_additions/deletions、time_updated
  —— 会话列表原料；`todo` 表 —— 任务列表原料
- `turn_usage` / `model_usage`：time_to_first_token_ms、token 细分
- schema 有 `schema_migration` 版本管理（13 个迁移），比裸读体面，
  但仍属内核私有：消费必须**只读 + 容错 + schema 不识别则降级隐藏**

一个容错的只读 db 消费模块同时解锁：准流式进度、工具 chip 升级、持久
历史、会话/任务列表。`--json` 总结对象另送上下文水位（contextUsed）。

0.2.0 已落地前两项（变更 db-live-progress-and-auth-screen）：迁移 id
白名单校验（子集判定，允许内核追加新迁移）、每拍新建只读连接 +
busy_timeout、任何读错误跳拍；会话锁定含全新会话的 prior 排除法
（fresh prompt 会创建新会话行,~1.6s 落库）；reasoning 采用"仅运行时
dim 单行"方案。

0.3.0 消费了另两项（变更 session-picker-and-ui-comfort）：`/sessions`
会话选择浮层（session 表,当前目录优先）与持久输入历史 + Ctrl+R
（input_history 表,只读合并,内核本就记录每条 --prompt）。todo 表视图
待观察到 headless 数据后再评估。

## 6. 安全设计

- **@提及越界防护**：canonicalize 后校验 `starts_with(cwd)` 且 `is_file()`，
  拒绝 `../`、绝对路径、目录、指向 cwd 外的符号链接
- **进程组终止**：取消任务连孙进程一起杀，无残留
- **密钥打码**：/auth 显示 env key 时首尾各 4 字符
- **wrapper 安全**：install.sh 探测不到内核时拒绝覆盖非托管 wrapper；
  托管文件带标记行，重复安装幂等
- 规划中：发送前 secret 特征扫描（防 .env 误粘贴）、本地审计日志

## 7. 跨平台设计

技术栈三平台通用（crossterm/ratatui/syntect-fancy 均无平台绑定，先例：Codex
CLI 三平台发布）。当前平台缝隙全部在集成层且已 `#[cfg(unix)]` 隔离：

| 缝隙 | Linux 现状 | macOS | Windows |
|---|---|---|---|
| 进程组终止 | killpg | 原样 | Job Object / taskkill /T |
| shell escape | sh -lc | 原样 | cmd /C |
| 内核定位 | /opt/ZCode + bash wrapper | ZCode.app/Contents/Resources | %LOCALAPPDATA%\Programs |
| 版本检测 | dpkg-query | Info.plist | 安装目录版本文件 |
| 配置路径 | HOME/XDG | 引入 dirs crate 统一 | 同左 |

移植顺序：macOS（半天）→ Windows（2-3 天）。共同地基：**内核定位逻辑从
bash wrapper 收进 TUI 内部**（同时消除对 install.sh 生成 wrapper 的依赖）。

### 7.1 SSH / 无桌面环境（第一使用场景）

TUI 自身零桌面依赖（已核查：无 xdg-open / 剪贴板 / 通知 / X11 调用；
/editor 走 $EDITOR，/login 在同一终端挂起执行）。缺口全在内核引导链，
2026-07-04 分析后的现状：

| 缺口 | 状态 |
|---|---|
| 内核获取：官方只发桌面 deb | 已通：`dpkg-deb -x` 免 root 解包到 `~/.local/opt/zcode/`，wrapper 自动探测 |
| 内核运行：Electron 动态链接 GUI 库，极简服务器缺库起不动 | 已修：wrapper 探测 Electron 可用性，回退系统 node ≥ 22.5（`ZCODE_FORCE_SYSTEM_NODE=1` 强制） |
| 安装：install.sh 假设目标机有 cargo | 已修：每版本 Release 发 musl 静态二进制；install.sh `--no-build` 只生成 wrapper |
| 登录：内核硬性要求 `~/.zcode/cli/config.json` 模型配置，**仅设 env API key 不够**（2026-07-04 实测） | 免浏览器路径已验证：`zcode login <zai\|bigmodel>-coding-plan-api-key <key>`（其网络验证环节可能失败，可按已挖出的 schema 手写 config.json，本机即此路生效）；`zcode login --no-browser` 打印 OAuth URL；或拷贝 config.json + credentials.json 两个文件 |
| 全链路验证 | 待做：干净无桌面容器（如 ubuntu:24.04）冒烟一遍解包→安装→prompt |
